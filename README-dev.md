# 抽屉 photo-drawer · 技术说明

Node 原生 `http` + sharp 生成缩略图，没有框架。**首页 `/` 是系列卡片**（一个文件夹 = 一个系列）；点卡片「查看」才到 `/view` 看照片（瀑布流 + 灯箱 + 目录菜单）。

## 启动

### 最简单：双击 `启动照片墙.bat`

在这个目录里双击 `启动照片墙.bat`：自动开一个黑色窗口跑服务，并自动用默认浏览器打开首页。

- **不要关那个黑窗口**，关掉就等于停止服务；
- **第一次启动会打开一个动画设置页**：先设密码、确认密码，再选照片文件夹（默认用程序自带的「我的照片」），两步就能用；之后每次打开就是同一个页面输密码；
- 端口被占用会自动换下一个；重复双击检测到已在运行时，直接帮你打开浏览器，不会起第二个；
- 脚本优先用程序自带的 `runtime/node.exe`，找不到才退回系统 node。

### 命令行启动

```powershell
cd photo-wall
node server.mjs                 # 默认自动打开浏览器
node server.mjs --no-open       # 不自动打开浏览器
node server.mjs "D:/照片"       # 临时指定照片目录（可传多个）
```

- 本机打开：http://127.0.0.1:3210 （系列卡片首页）；看图页：http://127.0.0.1:3210/view
- 手机/局域网：http://<本机IP>:3210 （服务监听 `0.0.0.0`；首次可能需要在管理员终端放行防火墙）
- 改完照片不用重启，刷新页面即可重新扫描；改了 `server.mjs` 才需要重启进程。

## 分享给别人：绿色包

想让朋友也能用，不用让他们装 Node——打成一个解压即用的绿色包：

```powershell
python pack.py    # 产物在 build/抽屉-绿色版.zip（约 40MB）
```

包里有：`server.mjs`、`public/`、精简后的 `node_modules`（只留 sharp 运行必需的 win64 原生库）、`runtime/node.exe`（内置运行时，对方无需安装）、`启动.bat`、空的「我的照片」文件夹和「使用说明.txt」。

对方的使用流程：**解压 → 双击「启动.bat」→ 浏览器自动打开 → 设置页先设密码、再选照片文件夹 → 完成**。

- 照片只在使用者自己的电脑里，不联网、不上传、无账号；
- 打包会自动排除 `config.json`、`.sessions.json`、`.thumbcache/`、日志、测试/截图等运行时与开发文件，**不会把你的密码和私人照片目录带出去**；
- `sharp` 是原生 `.node` 模块，所以走「内置 node.exe + 完整 node_modules」的绿色包路线，而不是单个 exe（单 exe 对原生模块支持差、未签名还会触发 SmartScreen 警告）。

## 照片目录在哪设置

普通用户**不用动代码**：第一次启动的引导页里选，选完写到 `config.json`，以后启动自动用。优先级从高到低：

| 方式 | 说明 |
| --- | --- |
| 命令行参数 | `node server.mjs "D:/照片" "E:/其他"`，临时覆盖，优先级最高 |
| 环境变量 | `set PHOTO_ROOTS=D:/照片;E:/其他`（用 `;` 分隔） |
| `config.json` | 引导页写出的 `photoDir`/`photoDirs`。**删掉它重启 → 重新进引导**（可用来改目录或重置密码） |
| 内置默认 | 程序自带的「我的照片」文件夹 |

引导页/`config.json` 里存的是纯路径文本，不再有旧版「JS 字符串反斜杠转义」的坑。

## 配置

运行配置现在放在 `config.json`（首次引导生成），代码里只剩默认值。常见可调项：

| 配置 | 说明 |
| --- | --- |
| `config.json` | 运行配置：`appName`（产品名）、`photoDir`/`photoDirs`（照片目录）、`passSalt`+`passHash`（密码**加盐哈希，不存明文**）、`port`、`host`。删除后重启会重新进引导 |
| 环境变量 | `PHOTO_ROOTS`（照片目录）、`PHOTO_PASS`（密码，自己用时直接覆盖，优先级最高）、`PORT`、`LISTEN`、`APP_NAME`、`NO_OPEN=1`（不自动开浏览器） |
| `PORT` / `HOST` | 端口 / 监听地址，默认 `3210` + `0.0.0.0`（局域网可访问）；被占用自动 +1 重试 |
| `TAB_ORDER` | 目录（顶部 tab）的固定顺序，例如 `['costume', 'iPhone']`。留空 `[]` = 按资源管理器的显示顺序 |
| `THUMB_W` | 缩略图宽度，默认 480（对应 240px 列宽的 2x 屏） |
| `MEM_CACHE_MAX` | 缩略图**内存缓存**上限，默认 128MB（另有 2000 张的条数上限，超了丢最久未用的） |
| `MEM_MIN_FREE` / `MEM_MAX_RSS` | 内存紧张的判定：系统可用内存 < 1GB 或 < 总量 10%、本进程 RSS > 1.5GB，满足其一即改用磁盘缓存 |
| `CACHE_MAX_BYTES` / `CACHE_MAX_FILES` | 缩略图**磁盘缓存**上限（默认 300MB / 5000 个），只在内存紧张时使用，超了自动 LRU 删最旧 |
| `TREE_TTL` / `SUB_TTL` | 目录列表缓存 60s / 单个目录的子目录树缓存 5 分钟 |

## 目录是怎么划分的

- 根目录下**每个顶层文件夹 = 一个目录**（抽屉里的一个可折叠分组），按资源管理器顺序排列（英文在前、中文按拼音、数字按数值，`新建文件夹 (2)` 排在 `(10)` 前面）。
- 目录内部如果还有**子文件夹**，会作为分支挂在它下面，可以一层层展开（支持任意深度）。
- 顺序浏览（默认排序「顺序 · 按文件夹」）= 目录顺序 → 子文件夹顺序 → 文件名顺序。
- 一个子目录、一张图都没有的顶层文件夹会被跳过（只看一层，很便宜）；隐藏目录（`.` 或 `$` 开头）一律跳过。
- 直接放在根目录下的散图会单独归到「根目录」分组（排在最后）。

## 系列卡片（首页 `/`）

打开 http://127.0.0.1:3210/ 就是卡片首页；老地址 `/series` 会 302 跳回 `/`。**一个文件夹 = 一个系列**：

- **层级**：照片根目录（在 `config.json` 里设置，默认用程序自带的「我的照片」）下的**每个顶层文件夹 = 一个系列**；系列里还有子文件夹就继续下钻，没有就直接看图。两层「根 → 系列」和三层「根 → 合集 → 系列」都适用。
- **交互**：卡片还有子目录时，点卡片下钻一层，面包屑返回；卡片右下角的「查看」按钮（Flow Button）跳 `/view` 看该目录的照片。顶部可筛选系列名，`?parent=<相对路径>` 可深链到某一层。
- **看图页 `/view`**：保留瀑布流、灯箱、目录菜单、搜索与排序，只在点「查看」时出现，不再是首页。深链 `/view#g=<目录 key>&sub=<子目录路径>&fg=<来源卡片组>&fp=<来源卡片层>`。
- **返回卡片页**：卡片页才是导航顶点。导航栏左侧固定「← 系列卡片」、目录抽屉第一项「返回系列卡片」、顶部「← 返回系列」——三处都按 `fg`/`fp` **原路回到进来时的那一级卡片页**，且任何时候都可见（包括停在「全部照片」时）。点「上一级」不会再误把整个照片库全部加载出来；确实想看全库，用目录抽屉里明确标注「整个照片库」的那一项。
- **视觉**：白色大圆角卡——大图在上 → 粗体名字 + 绿色徽章 → 灰色两行描述 → 底部统计与「查看」按钮（Flow Button：hover 时黑色圆从中心扩散、左右箭头换位、圆角收成 12px）。早期那套深色相框 / 全息箔 / 跟随光晕已整体去掉；卡片**不随鼠标倾斜**，hover 只有固定上浮，支持 `prefers-reduced-motion`。
- **封面**：固定用该系列按目录顺序找到的**第一张图片**（接口 `cover`），`object-position: center 28%` 按人像构图裁切，优先保住上半部；加载失败退成渐变占位。
- **信息量**：卡片上有系列全名、主标题、分册数、系列序号/总数、进入按钮；描述两行截断。**不统计照片数量**（那会拖慢首屏），统计行里的数字是子目录数，不是照片数。
- **手机端两卡并列**：`≤760px` 用 `repeat(2, minmax(0,1fr))`，卡片、字号、间距整体收紧但信息不删；`≤360px` 只隐藏第二项统计。
- **数据** `GET /api/series?parent=<相对路径>`：只读父目录一层和每个系列自己的一层，返回 `name / sub / dirs / cover`。`dirs` 是**直接子目录数**（不是照片数），`cover` 是 BFS 找到的第一张图（最多读 24 个目录）。**不递归全库、不统计照片数量**，13 张卡片毫秒级返回；`..` 一律回落到系列层，挡住目录穿越。
- **登录保护**：未登录访问 `/`、`/view` 都 302 到登录页，`/api/series` → 401。

## 全站背景

`public/soft-bg.css` 是首页（系列卡片）和看图页共用的背景（**后于各自样式加载**，用来覆盖各页原来的 body 底色）：上部淡青蓝珠光 → 下部纯白，整屏固定、无网格、无暗角，参考一张极简渐变图。这两页都在 `</head>` 前引入它；进入页 `/auth` 有自己的左右分栏配色（左灰紫渐变 + 右白），不引入。

- 看图页文字本来就是深色，只需把工具栏改成半透明白；
- 首页文字、导航栏、筛选框全部改成深色系；白色卡片用柔和的蓝灰阴影浮在浅底上；
- 要换风格只改 `soft-bg.css` 一个文件；想让某一页用回自己的背景，删掉那页的 `<link>` 即可。

## 没有「照片数量」

菜单和分区里**不显示每个目录有多少张**，因为你库里有几十万张照片、几千个目录，把数量数一遍要 **3.8 秒**（Windows 上逐个目录 `readdir` 很贵），首屏一直卡在等这一趟扫完，所以这项统计已经整个去掉了：

- 现在只有「加载出来多少张」这种运行时才知道的数字（`已加载 120 张` / `已全部加载（104 张）`）；
- 想要总数量就得把全库递归读一遍，代价就是那 3.8 秒，不值；
- 唯一例外：按时间/名称/大小排序时本来就要把当前范围全读进来，顺手算出的总数会正常显示。

## 进入页与登录授权

**首次设置和日常登录共用同一个页面** `public/auth.html`（+ `auth.css` / `auth.js`）。左边四个动画角色（紫/黑/橙/黄）：跟随鼠标、输密码时害羞转头、点开明文会凑过来看、密码错了摇头垮脸、验证成功一起咧嘴。

- **首次（还没有 config.json）**：第 1 步「设密码 + 确认密码」→ 点「确认密码」；第 2 步「选照片文件夹」（程序自带 / 系统对话框 / 手动输入）→ 点「开始使用」，服务端写配置并直接登录；
- **之后**：同一个页面只显示一个密码框；
- `?stay=1`：登录成功后停在原地（截图 / 演示用）。

打开页面**第一时间要求登录**，没登录的设备只能看到这个页面，主站的页面、接口、图片（`/api/*`、`/thumb`、`/img`）一律不放行：

- **密码**：第一次启动在进入页里设置，`config.json` 存的是**加盐哈希**（`passHash`），不存明文；自己用也可用环境变量 `PHOTO_PASS` 直接覆盖（优先级最高）。**忘记密码**：删掉 `config.json` 重启，重新进引导设置；
- **设备保持登录**：登录成功下发 `HttpOnly` Cookie（180 天），会话同时写到 `.sessions.json`，**服务重启也不掉线**；同一设备登一次就行，多台设备各自独立；
- **防暴力试密码**：连错 5 次锁 30 秒；
- 会话失效后前端会自动跳回登录页；`/login` 只在未登录时可见，已登录访问会被送回首页；
- 会话文件就是密码的唯一凭证，别把它交给别人。
- **改密码不影响已登录的设备**：它们靠 `.sessions.json` 里的令牌通行，不用重新输密码。想让所有设备立刻用新密码重登，删掉项目根目录的 `.sessions.json` 再重启服务即可。

## 缩略图缓存：内存优先，紧张才落盘

- **内存宽裕**（默认状态）：缩略图 webp 只放**内存**（LRU，上限 128MB / 2000 张，可调），命中零磁盘 IO，新图也不写硬盘。实测内存命中约 **0.4ms/张**，走硬盘约 2ms/张。
- **内存紧张**（系统可用内存 < 1GB 或 < 总量 10%，或本进程 RSS > 1.5GB）：自动切成**只走磁盘缓存**（`.thumbcache/`，300MB / 5000 张，LRU 自动清理），已在内存里的全部让位释放。
- 内存缓存放满不会溢出：超过上限就丢最久未用的。
- 服务重启后内存缓存清空属正常现象；硬盘里已有的缩略图会在第一次被访问时读一次、升进内存。
- 调试：响应头 `X-Thumb-Cache: mem|disk` 标明这张缩略图这次是从哪一层出的。

## 目录菜单（左上角）

目录很多时不用挤在顶栏里，全部收进左上角的折叠菜单。**首页和看图页都有这个按钮**，样式和行为只有一份（`nav.css` + `nav.js`）；在首页里点某个目录会直接跳去看图页看它的照片。

- **左上角「＋ 目录」按钮**：点击后抽屉滑入 —— 先两层色块错峰滑入，面板随后，目录行再逐行错峰浮入；按钮的 ＋ 旋转成 ×，文字在「目录 / 收起」间滚动切换。
- **抽屉内的目录树**：一条主干 + 每个子目录一段圆角分支线（branched menu 样式）。子目录要在**展开/选中那一刻才去扫**，所以抽屉秒开，不会因为目录多而卡住。
  - 点目录名 → 选中该目录（筛选照片）+ 自动展开；
  - 点目录前的箭头 → 只展开 / 收起，不改变筛选（第一次展开时才请求子目录树）；
  - 再点一次已选中的父目录 → 收起它的子级。
- **导航栏（两页同一套）**：左边是一个蓝色返回胶囊，右边是路径分段（rubber segment）。首页显示 `● 我的照片 | LS Studios`（胶囊是根目录名，带回根视图），看图页显示 `← 系列卡片 | 合集A | 2024 | 春`（胶囊回卡片页）。两页共用 `nav.css` 的 `.seg` 和 `nav.js` 的 `SegNav`，容器高度、字号、内边距、底色、圆角完全一致。切换层级时，白色选中块会先横向拉长盖住「起点 → 终点」的整段，再弹回目标段，像被橡皮筋拽了一下（实测宽度 37 → 65 → 49 → 52px：先拉长、再压过头、回到目标）。组名一级点它回卡片页，后面的子目录级在看图页内逐级回退；停在「全部照片」时显示 `← 系列卡片 | 全部照片`，**整行不再隐藏**。
- **目录抽屉顶部**：第一项「← 返回系列卡片」是看图页「上一级」的终点；第二项「全部照片 · 整个照片库」是明确的查看全库入口（目录多时加载较慢）。两者分开，不再混为一谈。
- 桌面端抽屉把内容推开（照片不会被盖住），窄屏（≤900px）则是浮层 + 遮罩，选中目录后自动收起。
- 深链保留：地址栏 `#g=<目录>&sub=<子目录>`，刷新后仍在同一目录；`Esc` 关闭抽屉。

## 设置（右上角齿轮）

首页和看图页的右上角都有齿轮按钮，改完立刻生效，**只保存在这台设备的 localStorage（`pw.prefs`）里**，刷新、关掉重开都还在；换设备/换浏览器就是各自的偏好。

| 分组 | 选项 | 说明 |
| --- | --- | --- |
| 浏览方式 | 卡片 / 瀑布流 | 卡片＝按系列浏览（默认）；瀑布流＝按顶层文件夹分区直接铺照片，滚到哪加载哪，点图开原图 |
| 卡片 | 纯白 / 玻璃 / 描边 | 玻璃＝照片铺满整卡，下半部分是渐进磨砂层（`backdrop-filter` + `mask` 从底部往上渐隐），名字/统计/按钮压在雾面上，外面一圈 5px 玻璃白边；描边＝透明底 + 细边框 |
| 背景色 | 淡青 / 暖砂 / 雾灰 / 薄暮 | 只换背景渐变，卡片和文字不动 |

实现拆成三层，互不干扰：

- `theme.css` 只定义变量（`--soft-*` 背景、`--card-*` 卡片），`html[data-bg]` / `html[data-card]` 切换；
- `prefs.js` 在 `<head>` 里同步执行，先写好 `data-bg` / `data-card` 再渲染，避免闪一帧默认色；
- `settings.js` 自动找 `.top-actions`（首页）或 `.controls`（看图页）插入按钮，面板是固定定位、点外面关闭。

视图切换由各页自己响应：首页监听 `view` 变化后重渲染（卡片 ↔ 瀑布流），看图页选「卡片」会跳回首页。

## 大照片库：按需加载（重要）

一个目录里放几十万、上百万张照片也不会撑爆内存，也不会卡首屏，因为**任何一步都不会把照片列表整体读进内存，启动时也不会把整个库递归走一遍**：

| 环节 | 做法 |
| --- | --- |
| 目录列表 | 只 `readdir` 根目录一层（`/api/tree`），13 个目录 **7ms** 回来 |
| 子目录树 | 点开某个目录时才扫它这一棵（`/api/subtree&g=`），扫完缓存 5 分钟；没点开的目录一次都不扫 |
| 照片列表 | 按页现读（`/api/photos?offset=&limit=`），只 `readdir` 当前这一页真正需要的目录 |
| 前端 | 分区懒加载：滚动到哪个分区才取那个分区的第一页；往下滚再自动取下一页 |
| 排序 | 默认「顺序 · 按文件夹」本身就是目录顺序，天然可流式分页 |
| 搜索 | 边扫边收，命中够一页就停 |

实测（30 万张 / 4000 个目录的库）：

| 操作 | 耗时 |
| --- | --- |
| 首屏目录列表 `/api/tree` | 7 ms（改造前：递归数完全库 3.8 秒） |
| 展开一个大目录（237 个子目录）`/api/subtree` | 34 ms / 15 KB |
| 某个目录的第一页照片 `/api/photos` | 19–33 ms / 36 KB |
| 浏览器首屏（13 个分区骨架 + 前 120 张缩略图） | 约 0.3 秒 |

几个上限（都在代码里可调）：

| 常量 | 默认 | 作用 |
| --- | --- | --- |
| `PAGE_MAX` | 240 | 单页最多返回多少张 |
| `SORT_CAP` | 40000 | 按时间/名称/大小排序需要读全量，超过这个数自动退回「顺序」排序（页面会提示） |
| `SEARCH_CAP` | 200000 | 单次搜索最多扫多少条目录项 |
| `TREE_TTL` | 60 s | 目录列表缓存时间；`/api/tree?refresh=1` 可强制重扫 |
| `SUB_TTL` | 5 min | 单个目录的子目录树缓存时间 |
| `AUTO_LOAD_MAX`（前端） | 2500 | 自动滚动加载的总量上限，超过后改为手动点「继续加载」 |

## 路由

| 路由 | 说明 |
| --- | --- |
| `/` | **首页 = 系列卡片**（`public/series.html` + `series.css` + `series.js`）。`?parent=<相对路径>` 深链到某一层；未登录 302 到 `/login` |
| `/series` | 老地址，302 跳回 `/` |
| `/view` | **看图页**（`public/view.html` + `view.css` + `view.js`）：瀑布流 / 灯箱 / 目录菜单，只从卡片「查看」进来，深链 `/view#g=...&sub=...`。同样需要登录 |
| `/soft-bg.css` | 首页和看图页共用的淡青蓝 → 纯白渐变背景 |
| `/nav.css`、`/nav.js` | 全局导航：目录抽屉 + 路径分段。首页和看图页共用一份，`nav.js` 同时提供 `DirMenu`（抽屉）和 `SegNav`（分段渲染） |
| `/masonry.css`、`/masonry.js` | 分区瀑布流：分区、分页、懒加载、列布局。首页的瀑布流模式和看图页共用 |
| `/theme.css` | 主题变量：背景 4 套 + 卡片 3 套，靠 `html[data-bg]` / `html[data-card]` 切换 |
| `/prefs.js` | 偏好存储（localStorage `pw.prefs`），`<head>` 里同步执行防闪烁 |
| `/settings.css`、`/settings.js` | 右上角设置按钮 + 面板 |
| `/login`、`/auth` | **进入页**（`auth.html` + `auth.css` + `auth.js`）：首次「设密码 → 确认 → 选文件夹」，之后输密码登录。`?stay=1` 成功后停在原地（截图 / 演示用） |
| `/setup` | 首次设置的别名，同样指向进入页；未配置时其它页面都 302 到这里 |
| `/auth.css`、`/auth.js` | 进入页的样式与脚本，**未登录时也放行**（否则登录页自己会加载不到样式） |
| `/api/login` | POST `{ pass }` 登录，成功下发 180 天 `HttpOnly` Cookie；连错 5 次锁 30 秒 |
| `/api/tree` | 目录列表：`{ roots, groups }`，只含「根目录 → 顶层文件夹」，**不递归、不数文件**。`?refresh=1` 强制重扫 |
| `/api/subtree?g=<目录 key>` | 某个目录的子目录树：`{ tree, own }`，`tree` 是嵌套的 `name / path / children`（**不带数量**），`own` 是该目录本层的图片数（用来决定要不要显示「根目录」分区） |
| `/api/series?parent=<相对路径>` | 系列卡片数据：`{ group, rootLabel, parent, crumbs, items, scanMs }`；`items[] = { name, sub, dirs, hasChildren, cover }`。只读两层、不递归、不数照片 |
| `/api/photos` | 分页取照片。参数 `g` 目录 key、`sub` 子目录路径、`loose=1` 只看本层、`offset`/`limit`、`sort`（`seq`/`time-desc`/`time-asc`/`name-asc`/`size-desc`）、`q` 搜索词。返回 `{ items, total, hasMore, sortUsed, offset, limit }`；`total` 只在全局排序时是数字，顺序分页时是 `null`（不统计） |
| `/thumb?p=<相对路径>` | 480px WebP 缩略图。**内存优先缓存**（128MB LRU），内存紧张时自动改用磁盘缓存；响应头 `X-Thumb-Cache: mem\|disk` 可看这一张从哪层出。ETag(304) |
| `/img?p=<相对路径>` | 原图，带 ETag(304) |

多根目录时 `p` 会带 `@根序号/` 前缀（如 `@0/costume/a.jpg`），避免不同根目录下同名文件冲突。路径会逐根校验，拒绝目录穿越、非图片和目录请求。
